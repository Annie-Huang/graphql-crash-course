The Do’s and Don’ts for your schema and GraphQL operations:
Schema Best Practices:
- Create a user entry point fo ryour authenticated users
- Evolve your graph based on client consumers use case
- Provide a schema that doesn't cause client consumer to manipulate the returned data
- Turn Introspection off in production and user a centralized schema repository for GraphQL tooling.

Operations Best Practice:
- Create a standard for naming operations in your organization/project
- Validate your GraphQL operations before shipping anything to production
- Attach client name and version to every operation's trace
- Evolve your operations with your client version number

    id,

If you want to get two things back in one network call:
query ExampleQuery {
  games: games {
    id
    platform
    title
  }
  reviews: reviews {
    content
    id
    rating
  }
}

you can also do (not explicit properties name is also fine, it will just use the operation name on the GQL side):
query ExampleQuery {
  games {
    id
    platform
    title
  }
  reviews {
    content
    id
    rating
  }
}
